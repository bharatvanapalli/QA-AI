**Fix (split the GOLD bar from the EXPORT bar — gold stays for KB/verdict only):**

### 2.3 DOM-EXCAVATION WAS DEAD SYSTEM-WIDE — FIXED ✅ (biggest find)
**Symptom:** `captureStructuralLocator` (the never-fail DOM-attribute reader: testid→id→name→label→aria→placeholder→css→nth) always returned `{ok:false}`. So NO element ever got its real DOM-attribute locator (`[name=...]`, `#id`, testid) — all locators came ONLY from accessibility-snapshot text.
**Root cause (single wrong param name):** the calls passed `ref` to `browser_evaluate`, but **@playwright/mcp 0.0.75 names that param `target`** (confirmed in `server/node_modules/@playwright/mcp/README.md`; matches the conductor's own "use target not ref" rule). With `ref` ignored, MCP ran a PAGE-level `page.evaluate(fnString)` with NO element bound → the function's `el` arg was undefined → `{ok:false}`.
**Fix:**
- `server/services/actionLocatorResolver.js` → `captureStructuralLocator()` (~line 2450) AND `inspectRef()` (~line 1249): `ref` → `target` in the `browser_evaluate` arguments.
- `server/services/mcp.js` → `parseEvaluateReturnValue()` (~line 3332): added `\n#{1,6}\s` to the section-break regex so it cuts at the trailing `### Ran Playwright code` markdown heading (otherwise JSON.parse failed on every object-returning evaluate). Unit-verified.
**Verified:** excavation now returns e.g. `locator('input[name="username"]')` (`ok:true, strat:name`).
**NOTE:** `inspectRef` uses the same pattern and was equally dead → fixing it likely improves locator resolution well beyond codegen. Re-test broadly.
