1. Purpose

This document specifies business requirements for QAAI's Authentication & Post-Login Access Control validation on OrangeHRM. This module is critical because it demonstrates QAAI's ability to:

Bind credentials from TestData.xlsx to login automation (no hardcoded passwords)

Assert role-specific UI elements post-login (what Admin sees vs ESS sees)

Handle validation errors and edge cases gracefully

Validate session state and logout functionality

Detect and prevent common security threats (SQL injection, brute force)

3. Business Requirements

3.1 Valid Login & Session Establishment

BR-AUTH-01: QAAI shall read credentials from AuthProfiles sheet (no hardcoding); inject username and password at login form.

BR-AUTH-02: QAAI shall login with Admin credentials (Admin / admin123) and assert redirect to /dashboard/index.

BR-AUTH-03: QAAI shall login with ESS credentials (ess_user_01 / TestUser@123) and assert redirect to /dashboard/index.

BR-AUTH-04: QAAI shall verify session is established — verify cookies set and subsequent requests include auth headers.

BR-AUTH-05: QAAI shall assert that post-login URL contains '/dashboard' or equivalent authenticated path.



3.2 Form Validation — Empty Fields

BR-FORM-01: QAAI shall submit login form with empty username and assert field-level validation error 'Username is required'.

BR-FORM-02: QAAI shall submit login form with empty password and assert field-level validation error 'Password is required'.

BR-FORM-03: QAAI shall submit with both fields empty and assert validation on both fields.

BR-FORM-04: QAAI shall verify error messages appear inline below respective fields, not generic alert.



3.3 Invalid Credentials & Error Handling

BR-ERROR-01: QAAI shall login with invalid username + valid password and assert error 'Invalid credentials'.

BR-ERROR-02: QAAI shall login with valid username + wrong password and assert error 'Invalid credentials'.

BR-ERROR-03: QAAI shall login with non-existent username and assert error message does NOT leak whether user exists.

BR-ERROR-04: QAAI shall assert error message is user-friendly and not a technical stack trace.

BR-ERROR-05: After invalid login, QAAI shall verify user remains on login page (no redirect).

BR-ERROR-06: QAAI shall verify error message is clearly visible (not hidden, proper color contrast).



3.4 Role-Based Post-Login Access Control

BR-RBAC-01: QAAI shall login as Admin and assert Admin menu item is visible in left navigation.

BR-RBAC-02: QAAI shall login as Admin and assert PIM, Leave, Time, Admin, Recruitment modules all visible.

BR-RBAC-03: QAAI shall login as ESS user and assert Admin menu item is NOT visible.

BR-RBAC-04: QAAI shall login as ESS user and assert only Leave, Time, My Info, Directory are visible.

BR-RBAC-05: QAAI shall assert user's name or avatar displays correctly in the top-right corner post-login.

BR-RBAC-06: QAAI shall verify that Admin dashboard shows admin-specific widgets (user management, system stats).

BR-RBAC-07: QAAI shall verify that ESS dashboard shows ESS-specific widgets (my info, my leave balance).



3.5 Session Management & Logout

BR-SESSION-01: QAAI shall login successfully and then logout via the top-right user menu.

BR-SESSION-02: QAAI shall verify logout redirects to /auth/login (login page).

BR-SESSION-03: QAAI shall verify session cookie is cleared after logout.

BR-SESSION-04: QAAI shall attempt to navigate directly to /dashboard after logout and assert redirect to /auth/login.

BR-SESSION-05: QAAI shall verify 'Remember Me' checkbox (if present) extends session timeout.



3.6 Security — Injection & Brute Force

BR-SEC-01: QAAI shall attempt SQL injection in username field (e.g., 'admin' OR '1'='1') and assert safe rejection.

BR-SEC-02: QAAI shall attempt XSS payload in username field (e.g., <script>alert(1)</script>) and assert payload not rendered.

BR-SEC-03: QAAI shall attempt multiple failed logins (5+) and assert account not locked (or lockout message shown).

BR-SEC-04: QAAI shall verify password field masks input (bullets, not plain text).

BR-SEC-05: QAAI shall verify no sensitive info (password hints, username suggestions) is exposed in UI.

5. Assumptions & Constraints

OrangeHRM demo at https://opensource-demo.orangehrmlive.com is publicly accessible; no VPN required.

Admin credentials (Admin / admin123) are fixed and displayed on the demo login page.

ESS user (ess_user_01) will be created via Admin > User Management during test setup.

No CAPTCHA or bot protection on the demo login page.

Session timeout is set to a reasonable value (>30 mins) to avoid timeout during test execution.

Password field properly masks input (uses HTML password input type, not text type).
